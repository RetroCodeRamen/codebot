# Configuration file parser

Build `confparse.py` in the root of the code directory: a parser for a small INI-like configuration format. Python 3, standard library only, no network.
The module provides `parse(text)`, `parse_file(path)` and the exception class `ParseError`. "Whitespace" below means spaces and tabs. Lines end with `\n` or `\r\n`.
The format has several rules that interact (comments, quotes, lists, continuation lines); every rule below is part of the contract, including the exact error phrases.

## Requirements

1. `parse(text)` returns a dict mapping each section name to a dict of that section's keys and values. A section header is a line `[name]`; whitespace around the name inside the brackets and before or after the whole header is ignored. A key line is `key = value`: the key and the value are trimmed of whitespace and the line is split at the FIRST `=`. Names (sections and keys) match `[A-Za-z_][A-Za-z0-9_.-]*`. Keys that appear before any section header belong to the section named `""` (empty string); that section only exists in the result if at least one such key exists. A section header that appears again continues the same section (the keys are merged). A section with no keys still appears in the result as `{}`. An empty value (`key =`) is the empty string. A `parse` argument that is not a `str` raises `TypeError`.

2. Comments: a line whose first non-whitespace character is `#` or `;` is a comment, and blank lines are ignored. An inline comment starts at the first `#` or `;` that is preceded by whitespace, outside quotes, and runs to the end of the line, so `a = b # note` has the value `"b"` but `a = b#c` has the value `"b#c"`, and `a = # only a comment` has the value `""`. An inline comment may also follow a section header.

3. Unquoted scalar values are typed after trimming: `true`, `false`, `yes`, `no`, `on`, `off` (any letter case) become `True`/`False` (`true`, `yes`, `on` are true); `null` (any case) becomes `None`; an optional sign followed by decimal digits becomes an `int` (`007` is `7`, `-5` is `-5`, `+3` is `3`); numbers of the exact forms `1.5`, `-0.25`, `1e3`, `2.5E-3` (digits, optional fraction with digits on both sides of the dot, optional exponent) become a `float`; everything else stays a `str` (including `1.`, `.5`, `0x10`, `1_000`, `1,5`).

4. Quoted values are always `str`, never typed (`"42"` is `"42"`, `'true'` is `"true"`), and keep inner whitespace, `#`, `;` and `=` as they are. Double-quoted strings understand exactly these escapes: `\n`, `\t`, `\r`, `\\`, `\"`; any other backslash escape is an error. Single-quoted strings have no escapes: a backslash is an ordinary character and the string ends at the next `'`. After the closing quote only whitespace or a comment may follow on that line.

5. Lists: a value that starts with `[` is a list. The elements are separated by commas, trimmed, and each one is an unquoted typed scalar (rule 3) or a quoted string (rule 4); a comma inside quotes does not separate. `[]` is the empty list, one trailing comma is allowed (`[1, 2,]` is `[1, 2]`), and lists cannot be nested. Only whitespace or a comment may follow the closing `]`. `tags = [a, "b, c", 3, true]` gives `["a", "b, c", 3, True]`.

6. Line continuation: a key line whose last character is a backslash continues on the next physical line. The backslash is removed and the next line's leading whitespace is dropped before the two are joined, repeatedly if needed, so the joined text is parsed as one line. This works for quoted strings and lists too (`a = "x \` followed by `y"` gives `"x y"`). Comment lines and section headers are never continued.

7. Errors raise `ParseError`, a subclass of `Exception`. Its attribute `line` is the 1-based number of the first physical line of the offending logical line, its attribute `message` is the description, and `str(error)` is `"line N: " + message`. The message contains the following phrases (compared ignoring case): a non-blank, non-comment, non-section line without `=` gives `missing '='`; an invalid key gives `invalid key`; an invalid section name gives `invalid section name`; a header without its `]` gives `unterminated section header`; other text after a section header gives `unexpected text after`; a key that already exists in the same section gives `duplicate key` followed by the quoted key name (`duplicate key 'port'`); an opening quote without its closing quote gives `unterminated string`; other text after a closing quote, or after the `]` of a list, gives `unexpected text after`; an unknown escape in a double-quoted string gives `unknown escape`; a list without its `]` gives `unterminated list`; a list inside a list gives `nested list`; an empty element such as in `[1,,2]` gives `empty list element`; a continuation backslash on the last line of the file gives `unexpected end of file`. The first error found, in file order, is the one raised.

8. `parse_file(path)` reads the file as UTF-8 (a leading byte order mark is ignored) and returns what `parse` returns for its text. A missing file raises the usual `FileNotFoundError`; parse errors are `ParseError` as above.
