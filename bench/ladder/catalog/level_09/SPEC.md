# Persistent background job system

Build `jobq.py` in the root of the code directory: a persistent job queue with workers, in one module. Python 3, standard library only (`sqlite3`, `threading`, `json`, `time`), no network.
Jobs live in an SQLite file so they survive restarts; workers run handlers with retries, timeouts, cancellation and crash recovery. Everything that depends on time uses the queue's `clock` function (default `time.time`), so tests can drive it with a fake clock; only handler timeouts and worker polling use real time.

## Requirements

1. Queue and jobs. `JobQueue(path=":memory:", clock=time.time, lease_seconds=30.0, retry_base=1.0, retry_cap=60.0)` opens or creates the database (`close()` and the context-manager protocol are supported). `enqueue(name, payload=None, *, priority=0, max_attempts=3, timeout=None, delay=0.0, key=None)` stores a job in state `queued` and returns its integer id (ids increase from 1). `name` is a non-empty string (stripped); `payload` must be JSON-serializable; `priority` and `max_attempts` are integers (`max_attempts >= 1`, a `bool` is not an integer); `timeout` is `None` or a positive number of seconds; `delay >= 0` seconds; `key` is `None` or a non-empty string; invalid arguments raise `ValueError`. The job's `run_at` is `clock() + delay`. A `key` makes enqueueing idempotent: a second `enqueue` with a key that already exists (in any state) returns the existing id and creates nothing. `get(job_id)` returns a `Job` dataclass with the fields `id, name, payload, state, priority, attempts, max_attempts, timeout, run_at, lease_expires, worker_id, cancel_requested, last_error, result, key, created, finished` (payload and result are decoded back from JSON, `cancel_requested` is a `bool`, `created` is the clock time of enqueueing); an unknown id raises `JobNotFound` (a subclass of `KeyError`). The states are `queued, running, succeeded, failed, cancelled`; `counts()` returns a dict with all five states as keys (0 when empty).

2. Claiming. `claim(worker_id)` atomically picks the next runnable job and returns it, or `None` if there is none. A job is runnable if it is `queued` and `run_at <= clock()`. Among runnable jobs the highest `priority` wins, then the earliest `run_at`, then the lowest id. Claiming sets the state to `running`, increases `attempts` by 1, stores the `worker_id` and sets `lease_expires = clock() + lease_seconds`; the returned `Job` reflects this. A job is never handed to two claimers: even with many threads or processes claiming at once, every job is returned by exactly one claim at a time. Jobs with a future `run_at` (delayed or waiting for a retry) are not returned.

3. Workers. `Worker(queue, handlers, worker_id=None, poll_interval=0.05)` runs jobs; `handlers` maps a job name to a function `handler(payload, ctx)`. `run_once()` claims one job, runs its handler and records the outcome, returning `True` if a job was processed and `False` if none was runnable. On success the job becomes `succeeded` with the handler's return value (JSON-serializable) stored as `result`; a result that cannot be serialized counts as a failed attempt with an error starting `TypeError`. `run_until_empty(max_jobs=None)` calls `run_once()` until nothing is runnable (or `max_jobs` jobs were processed) and returns how many jobs it processed. A job whose name has no handler fails at once, without retries, with `last_error == "LookupError: no handler for NAME"`. The context object `ctx` has the attributes `job_id` and `attempt` (the claimed attempt number), the property `cancelled`, the method `check()` (raises `Cancelled`, an `Exception`, if cancellation was requested) and `heartbeat()`. The queue methods `complete(job, result=None)` (returns `True` if accepted) and `fail(job, error, retry=True)` (returns the new state, or `None` if the attempt is not current) are the primitives the worker uses; they only apply to the attempt that was claimed: if the job is no longer `running` under that `worker_id` and `attempts` value (it timed out, was recovered, or was claimed again), the call changes nothing.

4. Retries. If a handler raises, the attempt failed with `last_error` set to `"<ExceptionClassName>: <message>"`. If `attempts < max_attempts` the job returns to `queued` with `run_at = clock() + min(retry_cap, retry_base * 2 ** (attempts - 1))` (so with `retry_base=1` the waits are 1, 2, 4, ... seconds, capped at `retry_cap`); otherwise it becomes `failed` and keeps its last error. `attempts` counts every claim. A job that succeeds after earlier failures ends `succeeded` with `last_error` reset to `None`. `fail(job, error, retry=False)` fails the job at once without retrying.

5. Timeouts. A job with a `timeout` must not run its handler for longer than that many real seconds: the worker runs the handler in its own thread and, when the time is up, records the attempt as failed with `last_error == "TimeoutError: job exceeded <timeout> seconds"` (`<timeout>` is the timeout written as a float: `0.3`, `1.0`) (retry rules as in requirement 4) and goes on with other work; the abandoned handler may keep running, but if it finishes later its result and exceptions are ignored and change nothing (neither a `succeeded` state nor a new failure), also if the job has been claimed again in the meantime. Jobs without a timeout may run as long as they need.

6. Cancellation. `cancel(job_id)` returns `"cancelled"` for a `queued` job (which becomes `cancelled` at once and is never run), `"requested"` for a `running` job (it sets `cancel_requested`; `ctx.cancelled` becomes `True`), and `False` for a job that has already finished; an unknown id raises `JobNotFound`. When a running job whose cancellation was requested ends in any way (success, failure, or `Cancelled` raised through `ctx.check()`), its state becomes `cancelled`, it is not retried, and a result is discarded. A handler that raises `Cancelled` without a pending request is a normal failure. A cancelled job keeps its `finished` time.

7. Crash recovery. A running job whose lease has expired (`lease_expires < clock()`) belongs to a worker that is presumed lost. `recover()` handles every such job and returns how many it handled: if `attempts < max_attempts` it goes back to `queued` with `run_at = clock()`, `worker_id` and `lease_expires` cleared and `last_error == "worker lost (lease expired)"`, otherwise it becomes `failed` with that error. `claim()` performs the same recovery first, so a lost job is picked up again by the next claim. `heartbeat(job)` (queue and `ctx.heartbeat()`) extends the lease to `clock() + lease_seconds` and returns `True`, or returns `False` if the attempt is no longer current. While a handler runs, the worker extends the lease itself at least every `lease_seconds / 3` seconds, so a long job is never recovered while its worker is alive. The attempt of a lost worker still counts in `attempts`.

8. Concurrency and persistence. Several `Worker` threads, or workers in several processes opened on the same database file, process the queue together: every job is executed exactly once when handlers succeed (50 jobs processed by 4 threads give 50 executions), and a retried job is never run in parallel with itself. `Worker.start(threads=1)` starts that many background threads that process jobs and poll every `poll_interval` seconds when idle (and returns the worker); `Worker.stop(wait=True)` stops them gracefully: threads finish the job they are running and then exit (with `wait=True` it returns after they ended). All state survives closing and reopening the queue on a file; a job that was `running` when the process died is recovered by the rules of requirement 7 once its lease has expired.
