# Modular notes application

Build a small notes application as the Python package `notes/` in the code directory: separate modules for the data model, validation, storage, search, import/export and a command-line interface.
Python 3, standard library only, no network. Run it as `python3 -m notes <command>`. The behaviour below is exact, including module names, function names, messages and exit statuses; independent tests import the package and run the command line.

## Requirements

1. `notes/models.py` defines the dataclass `Note` with the fields `id` (int), `title` (str), `body` (str, default `""`), `tags` (list of str, default empty), `created` (str, default `""`), `updated` (str, default `""`) and `pinned` (bool, default `False`), in this order. `note.to_dict()` returns a plain dict with exactly these keys; `Note.from_dict(d)` rebuilds a note from such a dict (missing `body`, `tags`, `created`, `updated`, `pinned` take their defaults, and the tag list is copied) so that `Note.from_dict(n.to_dict()) == n`.

2. `notes/validation.py` defines `ValidationError` (a subclass of `ValueError`) and three cleaning functions that return the cleaned value or raise `ValidationError` with exactly these messages. `clean_title(title)`: not a `str` -> `title must be a string`; after stripping whitespace empty -> `title must not be empty`; containing a newline -> `title must be a single line`; longer than 80 characters -> `title must be at most 80 characters`; otherwise the stripped title. `clean_body(body)`: not a `str` -> `body must be a string`; longer than 10000 characters -> `body must be at most 10000 characters`; otherwise the body unchanged. `clean_tags(tags)`: a `str` or anything that is not iterable -> `tags must be a list of strings`; an element that is not a `str` -> `tags must be a list of strings`; each tag is stripped and lowercased and must match `[a-z0-9][a-z0-9_-]{0,19}`, otherwise `invalid tag 'x'` (with the cleaned text); duplicates are dropped keeping the first; more than 10 tags -> `at most 10 tags are allowed`; the result is a list.

3. `notes/storage.py` defines `NoteNotFound` (a subclass of `KeyError`), `StorageError` (a subclass of `Exception`) and the class `NoteStore(path, clock=None)`. `clock` is a function returning the current time as an ISO string such as `2024-01-01T10:00:00`; by default the real local time in that format. The store keeps its notes in the JSON file `path`, written as `{"next_id": N, "notes": [note dicts]}`; a missing file is an empty store and the file is only created by the first change. Methods: `add(title, body="", tags=(), pinned=False)` validates with the cleaning functions, gives the note the next id (ids start at 1 and are never reused, even after deletions), sets `created` and `updated` from the clock and returns the `Note`; `get(id)` returns the note or raises `NoteNotFound(id)`; `update(id, **fields)` accepts only `title`, `body`, `tags`, `pinned` (anything else raises `TypeError`), validates, changes only the given fields, sets `updated` from the clock and returns the note, and a failed update changes nothing; `delete(id)` removes and returns the note; `all()` returns all notes sorted by id; `len(store)` is the number of notes; `restore(note)` inserts a `Note` exactly as given (id and timestamps kept; the id must be free, otherwise `ValueError`) and moves `next_id` beyond that id if needed. Every change is saved at once and atomically (never a partially written file). A file that is not valid JSON or lacks the structure makes the constructor raise `StorageError`, and the file is left untouched.

4. `notes/search.py` defines `search(notes, query="", tags=())`. The query is split on whitespace and lowercased; a note matches only if EVERY term occurs (case-insensitively) in its title, its body or its tags (the tags joined by a space). `tags` is a list of tags (compared in lowercase): a note must have all of them. A note's score is, for every term, 3 if it occurs in the title, plus 2 if it occurs in the tags, plus 1 if it occurs in the body, summed over all terms. The result is a list ordered by score (highest first), then pinned notes before unpinned ones, then by id. An empty query matches every note (all scores 0) and is then subject only to the tag filter.

5. `notes/transfer.py` defines `TransferError` (a subclass of `Exception`) and the export functions, each returning the number of notes written and writing the file atomically. `export_json(store, path)` writes `{"version": 1, "notes": [note dicts sorted by id]}`. `export_markdown(store, path)` writes the pinned notes first (then by id) as blocks: `# Title`, an empty line, `Tags: a, b` and an empty line (only if the note has tags), the body and an empty line (only if the body is not empty), then a line `---`; the blocks are separated by one empty line. For one unpinned note titled `T` with tag `x` and body `B` the file is exactly `# T\n\nTags: x\n\nB\n\n---\n`.

6. `import_json(store, path, on_conflict="skip")` of the same module reads a file written by `export_json` and returns `{"added": a, "skipped": s, "overwritten": o}`. A file that is not JSON, has no `"notes"` list or a `"version"` other than 1 raises `TransferError("not a valid notes export file")`; a note that fails validation (the same rules as 2, and its `id` must be an int) raises `TransferError("note N: <validation message>")` with its 1-based position, and in that case NOTHING is imported. A missing file raises `FileNotFoundError`. A note whose id is free is inserted with `restore` (id, created and updated kept). A note whose id already exists in the store is a conflict: `skip` leaves the existing note and counts it as skipped, `overwrite` updates the existing note's title, body, tags and pinned flag through `update` and counts it as overwritten, `duplicate` adds it as a new note with a new id and counts it as added. Any other `on_conflict` value raises `ValueError`.

7. `python3 -m notes` (implemented in `notes/__main__.py` and `notes/cli.py`, whose `main(argv, store=None, out=None)` returns the exit status) provides these commands. The data file is the environment variable `NOTES_FILE` (default `notes.json` in the current directory); when `NOTES_NOW` is set it is used as the clock (the same string for every timestamp). `add TITLE [--body B] [--tag T]... [--pin]` prints `Added note N`. `list [--tag T]... [--pinned]` prints one line per note, pinned notes first and then by id: the id right-aligned in 3 columns, a space, `*` if pinned else a space, a space, the title and ` #tag` for each tag; `--tag` filters (all tags required), `--pinned` keeps only pinned notes; no notes -> `No notes.`. `show ID` prints `Note N: TITLE`, `Created: ...`, `Updated: ...`, then `Tags: a, b` (only if it has tags), `Pinned` (only if pinned), an empty line and the body. `edit ID [--title T] [--body B] [--tag T]... [--pin | --unpin]` changes only what is given (the `--tag` options REPLACE all tags), prints `Updated note N`, and without any option fails with `nothing to edit`. `delete ID` prints `Deleted note N`. `search QUERY... [--tag T]...` prints the matches in the `list` format in the order of requirement 4, or `No matches.`.

8. Export, import and errors in the command line: `export PATH [--format json|markdown]` (default json) prints `Exported N note(s) to PATH`; `import PATH [--on-conflict skip|overwrite|duplicate]` (default skip) prints `Imported: added A, skipped S, overwritten O`. Errors are written to stderr as `Error: MESSAGE`. Exit status 0 on success, 1 if the note id does not exist (`Error: no note with id N`), 2 for everything else: a non-integer id (`Error: invalid note id 'x'`), validation errors (the message of requirement 2), a corrupt data file (`Error: data file is corrupt: PATH`), a bad import file or note (the `TransferError` message), a missing import file (`Error: no such file: PATH`), an invalid `--format` (`Error: invalid format 'x'`) or `--on-conflict` (`Error: invalid conflict mode 'x'`), and any usage error. Running with no command prints usage to stderr and exits with 2. `notes/__init__.py` exports `Note`, `ValidationError`, `NoteStore`, `NoteNotFound` and `StorageError`.
