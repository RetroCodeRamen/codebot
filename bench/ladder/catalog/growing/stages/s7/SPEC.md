# Notes application, stage 7: synchronisation between devices (amendment)

Everything required in stages 1 to 6 stays in force and its tests run again. Extend the existing application; databases of stage 6 or earlier must keep working. Python 3, standard library only.

## Requirements

1. Identity. Every database is one device with a `device_id` (attribute of `NoteStore`; random when not given; `NoteStore(path, clock=None, device_id=None)` uses the argument only when the database has none yet, then the id is kept for good). Every note has the keys `uid` (a string that is unique across all devices and never changes) and `device` (the device that made the last change). `add` assigns a new `uid`; `update` sets `device`; notes of an older database get a `uid` and this device when the database is opened (the schema version stays `1`). `export_json` keeps writing the stage 2 file format (no `uid`, `device`, `owner`, `reminder`).

2. Deletions. `delete` keeps a tombstone (uid, deletion time from the store clock, device) so that the deletion can be synchronised.

3. Snapshots. `NoteStore.snapshot()` returns `{"device", "notes": [{"uid", "title", "body", "tags", "created", "updated", "device"}], "tombstones": [{"uid", "deleted", "device"}]}`, notes and tombstones sorted by `uid`; it contains all notes, whoever owns them, but no owner, shares or reminders (these stay on the device). `apply_snapshot(snap)` merges a snapshot of ANOTHER device into this store and returns `{"applied": N, "conflicts": C}`: it is all-or-nothing (a snapshot that is not valid, or comes from this very device, raises `ValidationError` and changes nothing; all values are validated like normal input) and works per `uid` with the rule LAST WRITER WINS: the version with the larger `(time, device)` pair wins, time being `updated` of a note or `deleted` of a tombstone, device compared as a string. A newer note replaces the older one (title, body, tags, created, updated, device; the local id, owner, shares and reminder of an existing note stay) or creates it (new local id, no owner); a newer tombstone deletes the note and is stored; a note newer than a tombstone brings the note back (the tombstone is dropped); tombstones for notes that never existed here are stored too. `applied` counts the notes that were created, changed or deleted here; `conflicts` counts the notes where an edit (or a delete) made on THIS device and not yet exchanged with another device is overwritten by a newer, different version from the snapshot (the lost local edit). A device counts an edit as exchanged once a sync or an applied snapshot made both sides agree on it.

4. Two-way sync. `store.sync_with(other)` (`other` another `NoteStore`) merges both ways, so that afterwards both stores have identical snapshots apart from the `device` key, and returns `{"pulled": changes made here, "pushed": changes made on the other store, "conflicts": C}` (the lost edits of both sides added up). Calling it again right away reports zeros and changes nothing; the merge does not depend on which store starts it (the final content is the same), and it works for any number of devices in any order of pairwise syncs (they all converge once every pair has met after the last change). Syncing a store with itself or another store with the same device id is a `ValidationError`.

5. HTTP. A server made with `make_server(store)` (without `auth`) additionally has `GET /sync/snapshot` (`200`, the snapshot) and `POST /sync/apply` (body: a snapshot; `200` with the report, `422` for an invalid one, `400` for a body that is not a JSON object). With `auth=True` these routes do not exist (`404`). `sync_remote(store, base_url, timeout=30)` (module function) merges the store with such a server in both directions and returns the same report as `sync_with` (`pulled`, `pushed`, `conflicts`); an unreachable server or an error status raises `StoreError` with a message that starts with `sync failed`.

6. Command line. `device` prints the device id; `sync TARGET` merges with the database file TARGET (opened as a store) or, when TARGET starts with `http://` or `https://`, with that server, and prints `Synced with TARGET: pulled P, pushed Q, conflicts C`.
