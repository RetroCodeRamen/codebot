# Notes application, stage 6: reminders and background processing (amendment)

Everything required in stages 1 to 5 stays in force and its tests run again. Extend the existing application; existing databases (also those of stage 5) must keep working. Python 3, standard library only.

## Requirements

1. Reminders. Every note gets the key `reminder` (a time `YYYY-MM-DDTHH:MM:SS` or `None`). `NoteStore.set_reminder(note_id, due, actor=None)` sets it (any valid time, also in the past; anything else is a `ValidationError`) and returns the note; `clear_reminder(note_id, actor=None)` removes it. Both need write access to the note (the access rules of stage 5: `NotFound` for invisible notes, `PermissionDenied` for read-only shares) and a changed reminder counts as not yet fired.

2. Firing. `NoteStore.fire_due(now=None)` (default: the store clock) looks at all notes whose reminder is due (`reminder <= now`) and has not fired yet; for each it creates ONE notification for the note's owner (`user` is `None` for notes without an owner) with the message `Reminder: TITLE`, the time `now` as `ts`, and marks the reminder as fired. It returns the ids of the notes that fired, in id order. It is atomic and idempotent: a reminder fires exactly once, however often `fire_due` runs, also when many threads, worker objects or processes call it at the same time on the same database. Setting a new reminder time on a fired note arms it again; deleting a note drops its pending reminder, but notifications that were already created stay.

3. Notifications. `NoteStore.notifications(user=None, unread_only=False)` returns notification dicts `{"id", "note_id", "user", "message", "ts", "read"}` in id order, all of them, or only those of a user (names compare ignoring case; with `user=None` ALL notifications are returned, including those without a user), optionally only unread ones. `mark_read(ids, user=None)` marks notifications as read (with `user` only that user's own) and returns how many changed; unknown, already read or non-integer ids are ignored.

4. Worker. `Worker(store, interval=1.0, clock=None)` (in `notes.py`) runs the periodic jobs: `run_once(now=None)` calls `fire_due` and `purge_tokens` (which deletes expired login tokens, `expires <= now`, and returns how many) and returns `{"fired": [ids], "tokens_purged": n}`; it also stores it in `last_report`, increases `runs` and adds to `fired_total`. `start()` runs `run_once` in a daemon thread immediately and then every `interval` seconds and returns the worker (a second `start()` while running does nothing); an exception inside a run is stored in `last_error` as `"<ExceptionClass>: <message>"` and does not stop the thread; `stop()` stops the thread and waits for it (calling it without `start()` is harmless). `clock`, if given, supplies `now` instead of the store's clock.

5. HTTP. `PUT /notes/ID/reminder` with `{"due": "..."}` returns the note, `DELETE /notes/ID/reminder` returns the note without reminder (same rights, status codes and check order as the other note routes, validation errors are `422`), `GET /notifications[?unread=1]` returns `{"items": [...], "total": N}` (with `auth=True` only the token user's notifications, otherwise all), `POST /notifications/read` with `{"ids": [...]}` returns `{"marked": N}` (`422` if `ids` is not a list; with authentication only the user's own notifications can be marked).

6. Command line. `remind ID TIME` prints `Reminder set for note ID at TIME`, `remind ID --clear` prints `Reminder cleared for note ID` (without a time or `--clear` it fails with exit status 2); `worker --once` fires what is due and prints `Fired N reminder(s)`; `worker [--interval S]` without `--once` prints `Worker running`, then loops until it is terminated, printing `Fired reminder of note ID` for each reminder it fires; `notifications [--user U] [--unread]` prints one line per notification, `[ID] TS MESSAGE` followed by ` (new)` for unread ones, or `No notifications.`. A database of stage 5 or earlier opens unchanged (the schema version stays 1) and its notes have `reminder == None`; `export_json` still writes the stage 2 file format (no `owner`, no `reminder`).
