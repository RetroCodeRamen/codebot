# Shop pricing library

Build a small pricing library as three plain Python modules in the root of the code directory: `money.py`, `catalog.py` and `cart.py`. Python 3, standard library only, no third-party packages, no network. `catalog.py` uses `money.py`, and `cart.py` uses both. All amounts are whole numbers of cents (`int`).
Every function below must behave exactly as described. Where an exception is named, raise exactly that class.

## Requirements

1. `money.py` provides `parse_price(text)`, which turns a price written as text into cents. Surrounding whitespace is ignored and one leading `$` is allowed. The rest must be one or more digits, optionally followed by a dot and exactly one or two digits: `parse_price("12.34")` is `1234`, `parse_price("5")` is `500`, `parse_price("0.5")` is `50`, `parse_price(" $3.20 ")` is `320`. Anything else raises `ValueError`: `parse_price("1.234")` raises `ValueError`, and so do `""`, `"abc"`, `"-1"`, `".5"`, `"5."` and `"1.2.3"`.

2. `money.py` also provides `format_price(cents)`, which writes an amount with a dollar sign, a comma between each group of three dollar digits, and always two digits of cents: `format_price(1234)` is `"$12.34"`, `format_price(5)` is `"$0.05"`, `format_price(0)` is `"$0.00"`, `format_price(123456789)` is `"$1,234,567.89"`. A negative amount has the minus sign before the dollar sign: `format_price(-250)` is `"-$2.50"`. A value that is not an `int`, including `bool` and `float`, raises `TypeError`.

3. `catalog.py` provides `parse_catalog(text)`, which reads a price list with one product per line in the form `name: price` and returns a dict from product name to cents. The line is split at its first colon; the name is stripped of surrounding whitespace and lowercased, and the price follows the rules of `parse_price`. Blank lines and lines whose first non-whitespace character is `#` are ignored. `parse_catalog("Apple: 0.50\nGreen Pear: $1.20")` is `{"apple": 50, "green pear": 120}`. A line without a colon, an empty name, a bad price or a name that appears twice (after lowercasing) raises `ValueError`.

4. `catalog.py` also provides `lookup(catalog, name)`, which returns the price in cents of a product in a dict returned by `parse_catalog`. The name is stripped and lowercased before it is looked up, so `lookup({"apple": 50}, " APPLE ")` is `50`. A product that is not in the catalog raises `KeyError`.

5. `cart.py` provides `parse_items(text)`, which reads a shopping list such as `"apple x2, pear, apple"`. Entries are separated by commas; each entry is a product name optionally followed by whitespace, the letter `x` and a quantity of one or more digits. Names are stripped and lowercased, a missing quantity means 1, and entries for the same product are added together. The result is a list of `(name, quantity)` tuples in the order in which each product first appears: `parse_items("apple x2, pear, apple")` is `[("apple", 3), ("pear", 1)]`. An empty or whitespace-only text gives `[]`. An empty entry (as in `"apple,,pear"`), an empty name or a quantity of 0 raises `ValueError`.

6. `cart.py` also provides `subtotal(catalog_text, items_text)`, which returns the sum in cents of price times quantity over the shopping list, with the catalog given as text for `parse_catalog` and the list as text for `parse_items`: `subtotal("apple: 0.50\npear: 1.20", "apple x2, pear")` is `220`. An item that is not in the catalog raises `KeyError`.

7. `cart.py` also provides `discount(subtotal_cents, code)`, which returns the discount in cents for a discount code. Codes are compared without regard to case or surrounding whitespace. The empty code gives 0. `SAVE10` gives ten percent of the subtotal, rounded to the nearest cent with halves rounded up, so `discount(225, "save10")` is `23`. `FIVEOFF` gives 500 when the subtotal is at least 2000 and 0 otherwise: `discount(2000, "FIVEOFF")` is `500` and `discount(1999, "FIVEOFF")` is `0`. Any other code raises `ValueError`.

8. `cart.py` also provides `receipt(catalog_text, items_text, code="")`, which returns the receipt as one string of lines joined by `"\n"` with no trailing newline. There is one line per product of the shopping list, in its order, of the form `QTY x NAME @ UNIT = LINE` with the amounts written by `format_price`; then `Subtotal: AMOUNT`; then, only when the discount is greater than 0, `Discount: -AMOUNT`; then `Total: AMOUNT`, the subtotal minus the discount. `receipt("apple: 0.50", "apple x2")` is `"2 x apple @ $0.50 = $1.00\nSubtotal: $1.00\nTotal: $1.00"`.
